# M1 任务单：认证与账号、人员、班次、节假日

> 设计依据：`docs/design/architecture.md`（§3 模块、§4 数据表、§5 接口、§5.1 错误码、§6 安全）。
> 界面依据：`docs/design/prototype/index.html`（原型 v0.2）。

## 0. 总览

M1 分 4 个功能组，按“每张单 ≤ 200 行”拆成 15 张任务单：

| 功能组 | 目标 | 任务单 |
|---|---|---|
| A 认证与账号 | 账号密码登录、登录失败锁定、首次强制改密、按角色鉴权、科长管理账号、大屏账号 | M1-01 ~ M1-09 |
| B 人员 | 人员增删改、停用、排序；新增人员自动建登录账号 | M1-10、M1-11 |
| C 班次 | 查看 6 种班次，科长修改名称/时间/工时/颜色/启用 | M1-12、M1-13 |
| D 节假日 | 按年录入放假日与调休上班日，从上一年复制 | M1-14、M1-15 |

### 依赖与派发顺序

```
M1-01 用户实体 ─> M1-02 JWT ─> M1-03 安全配置 ─> M1-04 操作日志 ─> M1-05 登录接口
M1-05 ─┬─> M1-06 账号接口 ─┬─> M1-12 班次接口 ─> M1-13 班次页（还依赖 M1-07）
       │                   ├─> M1-14 节假日接口 ─> M1-15 节假日页（还依赖 M1-07）
       │                   └─> M1-09 账号页（还依赖 M1-07）
       ├─> M1-07 前端登录 ─> M1-08 改密页
       └─> M1-10 人员接口 ─> M1-11 人员页（还依赖 M1-07）
```

- 第 1 批：M1-01 → M1-02 → M1-03 → M1-04 → M1-05（后端地基，串行）
- 第 2 批：M1-06、M1-07、M1-10（可并行）
- 第 3 批：M1-08、M1-09、M1-11、M1-12、M1-14（可并行）
- 第 4 批：M1-13、M1-15

### 通用约定（每张任务单都适用）

1. **分支**：从最新 `main` 拉分支 `m1-XX-<英文短名>`，完成后提 PR 到 `main`，由人工合并。
2. **开发环境**：只使用本机 Docker Compose 启动的测试库。复制 `.env.example` 为 `.env`，自行填写测试用的随机值（`PBB_JWT_SECRET` 至少 32 个字符）。**`.env` 禁止提交。**
3. **启动**：`docker compose up -d --build`，访问 `http://localhost:8090`。
4. **后端测试**（本机没有 Maven 时用容器跑）：
   ```bash
   docker run --rm -v "$PWD/backend":/src -w /src maven:3.9-eclipse-temurin-17 mvn -s settings.xml -q test
   ```
5. **前端检查**：`cd frontend && npm install && npm run build` 必须成功。
6. **返回体**：Controller 一律返回 `ApiResponse.ok(data)`；业务错误抛 `new BizException(code, message)`，错误码见 architecture §5.1。
7. **日志**：禁止在日志、操作日志、异常信息里输出密码、临时密码、token、完整手机号。
8. **不得修改**：`backend/src/main/resources/db/migration/V1__init_schema.sql`（表结构已定，需要改表请先找规划者）、`docker-compose.yml`、`.env.example`、`scripts/**`、`docs/**`。
9. **curl 验收**里的 `$TOKEN`、`$ADMIN_PW` 是 shell 变量，由执行者在本机设置，不要写进代码或提交。

**背景**：认证模块的地基。定义 `app_user` 的 JPA 实体，提供密码强度校验、临时密码生成，并在首次启动时自动创建管理员 `admin`。

**禁止修改**：`V1__init_schema.sql`、`application.yml`；**不要**引入 `spring-boot-starter-security`（M1-03 才加，提前加会让所有接口被默认登录页拦截）。

**接口定义**

```xml
<!-- pom.xml 新增，版本由 Spring Boot 管理，不写 version -->
<dependency>
  <groupId>org.springframework.security</groupId>
```

```java
package com.hospital.pbb.user;

public enum Role { ADMIN, MEMBER, SCREEN }

@Entity
@Table(name = "app_user")
public class AppUser {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;
    @Column(nullable = false, length = 32, unique = true) private String username;
    @Column(name = "password_hash", nullable = false, length = 100) private String passwordHash;
    @Column(name = "display_name", nullable = false, length = 32) private String displayName;
    @Enumerated(EnumType.STRING) @Column(nullable = false, length = 16) private Role role;
    @Column(name = "staff_id") private Long staffId;
    @Column(nullable = false) private boolean enabled = true;
    @Column(name = "must_change_password", nullable = false) private boolean mustChangePassword = true;
    @Column(name = "failed_attempts", nullable = false) private int failedAttempts = 0;
    @Column(name = "locked_until") private OffsetDateTime lockedUntil;
    @Column(name = "last_login_at") private OffsetDateTime lastLoginAt;
    @Column(name = "created_at", nullable = false, updatable = false) private OffsetDateTime createdAt = OffsetDateTime.now();
    @Column(name = "updated_at", nullable = false) private OffsetDateTime updatedAt = OffsetDateTime.now();
    // 为以上所有字段生成 getter / setter
}

public interface AppUserRepository extends JpaRepository<AppUser, Long> {
    Optional<AppUser> findByUsername(String username);
    boolean existsByUsername(String username);
    List<AppUser> findAllByOrderByIdAsc();
}

/** 登录后放进 SecurityContext 的当前用户 */
public record AuthUser(Long id, String username, Role role, Long staffId) {}

public final class PasswordUtil {
    /** 8~64 位可见 ASCII 字符（不含空格），至少 1 个字母和 1 个数字 */
    public static final String STRONG_REGEX = "^(?=.*[A-Za-z])(?=.*\\d)[\\x21-\\x7E]{8,64}$";
    public static boolean isStrong(String password);      // null → false
    public static String randomTempPassword();            // 见实现要点 3
}

@Configuration
public class PasswordConfig {
    @Bean public PasswordEncoder passwordEncoder() { return new BCryptPasswordEncoder(); }
}

@Component
public class AdminInitializer implements ApplicationRunner {
    public AdminInitializer(AppUserRepository repo, PasswordEncoder encoder,
                            @Value("${pbb.admin-init-password}") String initPassword);
    @Override public void run(ApplicationArguments args);
}
```

**实现要点**
1. 按上面代码建 `Role`、`AppUser`、`AppUserRepository`、`AuthUser`、`PasswordConfig`。
2. `isStrong`：`password != null && password.matches(STRONG_REGEX)`。
3. `randomTempPassword`：用 `SecureRandom` 从字符集 `ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnpqrstuvwxyz23456789` 里取 10 个字符；如果结果不满足 `isStrong` 就重新生成，直到满足为止。
4. `AdminInitializer.run`：如果 `repo.existsByUsername("admin")` 为 true，直接返回。
5. 否则检查 `initPassword`：为空、等于 `change-me` 或以 `<` 开头时，抛 `IllegalStateException("PBB_ADMIN_INIT_PASSWORD 未配置")`。
6. 创建 `AppUser`：username=`admin`，displayName=`科长`，role=`ADMIN`，passwordHash=`encoder.encode(initPassword)`，mustChangePassword=`true`，然后保存。
7. 输出 `log.info("已创建初始管理员 admin")`，**不要输出密码**。

**验收标准**
- 单元测试 `PasswordUtilTest` 全部通过：

| 输入 | 期望 |
|---|---|
| `isStrong("abc12345")` | `true` |
| `isStrong("abcdefgh")` | `false` |
| `isStrong("12345678")` | `false` |
| `isStrong("ab1")` | `false` |
| `isStrong("abc 12345")` | `false` |
| `isStrong(null)` | `false` |
| 循环 100 次 `randomTempPassword()` | 每次长度都是 10，且 `isStrong` 为 `true` |

- 集成验收（`.env` 里已设置 `PBB_ADMIN_INIT_PASSWORD`）：
  1. `docker compose up -d --build` 后执行 `docker compose exec db psql -U pbb -d pbb -c "select username, role, must_change_password from app_user"`，输出**一行** `admin | ADMIN | t`。
  2. `docker compose restart backend` 后再查一次，仍然只有一行。
  3. `docker compose logs backend` 里有“已创建初始管理员 admin”，并且只出现一次；日志里搜不到初始密码。

**规模**：约 150 行。**依赖**：无。

## M1-02 新增 JWT 签发与解析工具

**背景**：登录成功后签发 token，之后每次请求都靠它识别用户。本单只做工具类，不接入请求链路。

**允许修改的文件**
- `backend/pom.xml`（只新增 3 个 jjwt 依赖）
- `backend/src/main/java/com/hospital/pbb/auth/JwtClaims.java`（新建）
- `backend/src/main/java/com/hospital/pbb/auth/JwtService.java`（新建）
- `backend/src/test/java/com/hospital/pbb/auth/JwtServiceTest.java`（新建）

**禁止修改**：`application.yml`（`pbb.jwt-secret` 已存在）、`user/**`。

**接口定义**

```xml
<dependency><groupId>io.jsonwebtoken</groupId><artifactId>jjwt-api</artifactId><version>0.12.6</version></dependency>
<dependency><groupId>io.jsonwebtoken</groupId><artifactId>jjwt-impl</artifactId><version>0.12.6</version><scope>runtime</scope></dependency>
<dependency><groupId>io.jsonwebtoken</groupId><artifactId>jjwt-jackson</artifactId><version>0.12.6</version><scope>runtime</scope></dependency>
```

```java
package com.hospital.pbb.auth;

public record JwtClaims(Long userId, String username, Role role) {}

@Service
public class JwtService {
    public static final Duration TTL_DEFAULT = Duration.ofHours(12);
    public static final Duration TTL_SCREEN  = Duration.ofDays(30);

    @Autowired
    public JwtService(@Value("${pbb.jwt-secret}") String secret) { this(secret, Clock.systemDefaultZone()); }
    JwtService(String secret, Clock clock);          // 包级可见，供测试注入时钟

    public String issue(AppUser user);
    public Optional<JwtClaims> parse(String token);  // 任何异常（格式错、签名错、过期、null）都返回 Optional.empty()
}
```

**实现要点**
1. 构造函数：`secret.getBytes(UTF_8).length < 32` 时抛 `IllegalStateException("PBB_JWT_SECRET 至少 32 字节")`；否则 `Keys.hmacShaKeyFor(bytes)` 生成密钥。
2. `issue`：subject = `user.getId().toString()`，claim `u` = username，claim `r` = `role.name()`；签发时间取 `clock.instant()`；过期时间：SCREEN 用 `TTL_SCREEN`，其他角色用 `TTL_DEFAULT`；使用 HS256 签名。
3. `parse`：`Jwts.parser().verifyWith(key).clock(() -> Date.from(clock.instant())).build().parseSignedClaims(token)`，读出 3 个字段组装 `JwtClaims`；整个过程包在 `try/catch (Exception)` 里，出错返回 `Optional.empty()`。

**验收标准**（`JwtServiceTest`，密钥用 `"0123456789abcdef0123456789abcdef"`，签发时钟固定为 `2026-10-01T09:00:00+08:00`）

| 用例 | 期望 |
|---|---|
| 用户 id=1、username=`admin`、role=ADMIN，签发后用同一个 service 解析 | 解析结果为 `JwtClaims(1, "admin", ADMIN)` |
| `parse("abc")` | `Optional.empty()` |
| `parse(null)` | `Optional.empty()` |
| 用另一个 32 字节密钥的 service 解析上面的 token | `Optional.empty()` |
| MEMBER 的 token，用时钟 +11 小时的 service 解析 | 有值 |
| MEMBER 的 token，用时钟 +13 小时的 service 解析 | `Optional.empty()` |
| SCREEN 的 token，用时钟 +29 天的 service 解析 | 有值 |
| SCREEN 的 token，用时钟 +31 天的 service 解析 | `Optional.empty()` |
| `new JwtService("short", clock)` | 抛 `IllegalStateException` |

**规模**：约 120 行。**依赖**：M1-01（用到 `AppUser`、`Role`）。

## M1-03 接入 Spring Security 与 JWT 过滤器

**背景**：让除健康检查和登录以外的所有 `/api/**` 接口都必须登录，并在请求里识别当前用户和角色；首次登录没改密码的账号只能访问改密相关接口。

**允许修改的文件**
- `backend/pom.xml`（只新增 `spring-boot-starter-security`）
- `backend/src/main/java/com/hospital/pbb/auth/SecurityConfig.java`（新建）
- `backend/src/main/java/com/hospital/pbb/auth/JwtAuthFilter.java`（新建）
- `backend/src/main/java/com/hospital/pbb/auth/JsonErrorWriter.java`（新建）
- `backend/src/main/java/com/hospital/pbb/common/GlobalExceptionHandler.java`（只新增 handler 方法）
- `backend/src/test/java/com/hospital/pbb/auth/JwtAuthFilterTest.java`（新建）

**禁止修改**：`JwtService.java`、`user/**`、`HealthController.java`。

**接口定义**

```java
package com.hospital.pbb.auth;

@Component
public class JsonErrorWriter {
    public JsonErrorWriter(ObjectMapper objectMapper);
    /** 写出 HTTP status + {"code":code,"message":message,"data":null}，Content-Type: application/json;charset=UTF-8 */
    public void write(HttpServletResponse resp, int httpStatus, int code, String message) throws IOException;
}

/** 不加 @Component，由 SecurityConfig 手动 new，避免被注册成两次 Servlet 过滤器 */
public class JwtAuthFilter extends OncePerRequestFilter {
    public static final Set<String> MUST_CHANGE_WHITELIST =
        Set.of("/api/auth/me", "/api/auth/change-password", "/api/auth/logout");
    public JwtAuthFilter(JwtService jwtService, AppUserRepository userRepo, JsonErrorWriter writer);
    @Override protected void doFilterInternal(HttpServletRequest req, HttpServletResponse resp, FilterChain chain);
}

@Configuration
@EnableMethodSecurity
public class SecurityConfig {
    @Bean public SecurityFilterChain filterChain(HttpSecurity http, JwtService jwt,
                                                 AppUserRepository repo, JsonErrorWriter writer) throws Exception;
}
```

GlobalExceptionHandler 新增：

```java
@ExceptionHandler(AccessDeniedException.class)            // org.springframework.security.access
@ResponseStatus(HttpStatus.FORBIDDEN)
public ApiResponse<Void> handleDenied(AccessDeniedException e) { return ApiResponse.fail(403, "无权限"); }

@ExceptionHandler({HttpMessageNotReadableException.class, MissingServletRequestParameterException.class,
                   MethodArgumentTypeMismatchException.class})
@ResponseStatus(HttpStatus.BAD_REQUEST)
public ApiResponse<Void> handleBadRequest(Exception e) { return ApiResponse.fail(400, "参数错误"); }

@ExceptionHandler(NoResourceFoundException.class)
@ResponseStatus(HttpStatus.NOT_FOUND)
public ApiResponse<Void> handleNotFound(NoResourceFoundException e) { return ApiResponse.fail(404, "接口不存在"); }
```

**实现要点**
1. `SecurityConfig`：关闭 csrf、formLogin、httpBasic、logout；session 设为 `STATELESS`。
2. 放行 `/api/health`、`/api/auth/login`、`/actuator/health/**`；`/api/**` 要求 `authenticated()`；其余 `permitAll()`。
3. `exceptionHandling`：authenticationEntryPoint 用 `writer.write(resp, 401, 401, "未登录或登录已过期")`；accessDeniedHandler 用 `writer.write(resp, 403, 403, "无权限")`。
4. `http.addFilterBefore(new JwtAuthFilter(jwt, repo, writer), UsernamePasswordAuthenticationFilter.class)`。
5. `JwtAuthFilter`：读取 `Authorization` 头；不是以 `Bearer ` 开头就直接 `chain.doFilter` 并 return。
6. 截取 token 后调用 `jwtService.parse`；为空就直接 `chain.doFilter` 并 return。
7. 用 `userRepo.findById(claims.userId())` 查用户；用户不存在或 `enabled=false` 时直接 `chain.doFilter` 并 return（后续由入口点返回 401）。
8. 构造 `AuthUser(id, username, role, staffId)`，权限设为 `List.of(new SimpleGrantedAuthority("ROLE_" + role.name()))`，放进 `SecurityContextHolder`。
9. 如果 `user.isMustChangePassword()` 为 true，且 `req.getRequestURI()` 不在 `MUST_CHANGE_WHITELIST` 里：调用 `writer.write(resp, 403, 4031, "请先修改初始密码")`，然后 return，不调用 chain。
10. 其他情况调用 `chain.doFilter`。

**验收标准**
- `JwtAuthFilterTest`（Mockito mock `JwtService`、`AppUserRepository`，用 `MockHttpServletRequest/Response` 和 `MockFilterChain`；每个用例前后调用 `SecurityContextHolder.clearContext()`）：

| 用例 | 期望 |
|---|---|
| 请求没有 Authorization 头 | chain 被调用；`SecurityContextHolder.getContext().getAuthentication()` 为 null |
| 有效 token；用户 id=1、ADMIN、启用、mustChange=false；URI `/api/staff` | chain 被调用；principal 等于 `AuthUser(1,"admin",ADMIN,null)`；权限包含 `ROLE_ADMIN` |
| 有效 token；用户已停用 | chain 被调用；authentication 为 null |
| 有效 token；mustChange=true；URI `/api/staff` | 响应状态 403，body 含 `"code":4031`；chain **未**被调用 |
| 有效 token；mustChange=true；URI `/api/auth/me` | chain 被调用 |

- curl 验收：
  - `curl -s -o /dev/null -w "%{http_code}" http://localhost:8090/api/health` → `200`
  - `curl -s http://localhost:8090/api/staff` → HTTP 401，body `{"code":401,"message":"未登录或登录已过期","data":null}`
  - `curl -s -H "Authorization: Bearer abc" http://localhost:8090/api/staff` → HTTP 401

**规模**：约 170 行。**依赖**：M1-01、M1-02。

## M1-04 新增操作日志服务

**背景**：所有写操作都要留痕（设计 §6）。本单提供统一的记录方法，后续各模块直接调用。

**允许修改的文件**
- `backend/src/main/java/com/hospital/pbb/oplog/OperationLog.java`（新建）
- `backend/src/main/java/com/hospital/pbb/oplog/OperationLogRepository.java`（新建）
- `backend/src/main/java/com/hospital/pbb/oplog/OpAction.java`（新建）
- `backend/src/main/java/com/hospital/pbb/oplog/OpLogService.java`（新建）
- `backend/src/test/java/com/hospital/pbb/oplog/OpLogServiceTest.java`（新建）

**禁止修改**：`auth/**`、`user/**`。本单**不做**日志查询接口（属于 M3）。

**接口定义**

```java
package com.hospital.pbb.oplog;

@Entity @Table(name = "operation_log")
public class OperationLog {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;
    @Column(name = "user_id") private Long userId;
    @Column(length = 32) private String username;
    @Column(nullable = false, length = 32) private String action;
    @Column(length = 100) private String target;
    @Column(length = 500) private String detail;
    @Column(length = 45) private String ip;
    @Column(name = "created_at", nullable = false) private OffsetDateTime createdAt = OffsetDateTime.now();
    // getter / setter
}

public interface OperationLogRepository extends JpaRepository<OperationLog, Long> {}

public final class OpAction {
    public static final String LOGIN = "登录", LOGIN_FAIL = "登录失败", LOGOUT = "登出",
        CHANGE_PASSWORD = "修改密码", RESET_PASSWORD = "重置密码", UNLOCK_USER = "解锁账号",
        DISABLE_USER = "停用账号", ENABLE_USER = "启用账号", CREATE_USER = "新增账号",
        CREATE_STAFF = "新增人员", UPDATE_STAFF = "修改人员", SORT_STAFF = "调整人员排序",
        UPDATE_SHIFT = "修改班次",
        CREATE_HOLIDAY = "新增节假日", UPDATE_HOLIDAY = "修改节假日", DELETE_HOLIDAY = "删除节假日",
        COPY_HOLIDAY = "复制节假日";
    private OpAction() {}
}

@Service
public class OpLogService {
    /** 当前登录用户从 SecurityContext 取（principal 为 AuthUser）；未登录则 userId/username 为 null */
    public void record(String action, String target, String detail);
    /** 登录场景：此时 SecurityContext 里还没有用户，显式传入 */
    public void recordAs(Long userId, String username, String action, String target, String detail);
}
```

**实现要点**
1. `record`：读 `SecurityContextHolder.getContext().getAuthentication()`，principal 是 `AuthUser` 时取 id 和 username，否则都为 null；然后调用 `recordAs`。
2. `recordAs`：新建 `OperationLog`，target 截断到 100 个字符，detail 截断到 500 个字符（null 保持 null）。
3. IP：`RequestContextHolder.getRequestAttributes()` 是 `ServletRequestAttributes` 时，优先取请求头 `X-Forwarded-For` 按逗号分隔的第一个值（trim 后），没有该头就取 `getRemoteAddr()`；不在请求上下文里时为 null。
4. 调用 `repository.save`。
5. 类注释写明：**detail 里禁止写密码、token、手机号**。

**验收标准**（`OpLogServiceTest`，mock Repository 并用 `ArgumentCaptor` 捕获保存的对象）

| 用例 | 期望 |
|---|---|
| SecurityContext 为 `AuthUser(7,"IT001",MEMBER,3)`；请求 remoteAddr=`127.0.0.1`，无 XFF；`record("新增人员","IT002","x")` | userId=7，username=`IT001`，action=`新增人员`，ip=`127.0.0.1` |
| 请求头 `X-Forwarded-For: 127.0.0.2, 127.0.0.3` | ip=`127.0.0.2` |

6. `me`：`findById`，查不到时抛 `BizException(1100, "账号不存在")`。
