## M5-01 新增删除人员用的日志清理方法与日志动作名

**背景**：删除人员时要一并删除与此人相关的操作日志（§9.4）。本单只在 oplog 包里提供方法，由 M5-07 调用；同时放好 M5 全部日志动作名，避免多张单子改同一个文件。

**允许修改的文件**
- `backend/src/main/java/com/hospital/pbb/oplog/OpAction.java`（只新增 3 个常量）
- `backend/src/main/java/com/hospital/pbb/oplog/OperationLogRepository.java`
- `backend/src/main/java/com/hospital/pbb/oplog/OpLogService.java`（只新增 `purgeStaff` 方法）
- `backend/src/test/java/com/hospital/pbb/oplog/OpLogServiceTest.java`（只新增用例）

**禁止修改**：`OperationLog.java`、`OpLogQueryService.java`、`OpLogController.java`、任何其他包。

**接口定义**

```java
// OpAction 新增
public static final String DELETE_STAFF = "删除人员";
public static final String IMPORT_STAFF = "导入人员";
public static final String EXPORT_STAFF = "导出人员";

// OperationLogRepository 新增（import org.springframework.data.jpa.repository.Modifying / Query、org.springframework.data.repository.query.Param）
@Modifying
@Query("delete from OperationLog l where l.userId = :userId")
int deleteByUserId(@Param("userId") Long userId);

@Modifying
@Query("delete from OperationLog l where l.target = :target")
int deleteByTarget(@Param("target") String target);

@Modifying
@Query("delete from OperationLog l where l.action = :action and l.target like :prefix")
int deleteByActionAndTargetLike(@Param("action") String action, @Param("prefix") String prefix);

@Modifying
@Query("delete from OperationLog l where l.action = :action and l.detail = :detail")
int deleteByActionAndDetail(@Param("action") String action, @Param("detail") String detail);

// OpLogService 新增
/**
 * 删除人员时清理与此人相关的日志，返回删除条数。
 * userId 为 null 时跳过第 1 条规则；byName=false 或姓名含 % / _ 时跳过按姓名的两条规则。
 */
@Transactional
public int purgeStaff(Long userId, String empNo, String name, boolean byName)
```

**实现要点**
1. `total = 0`。
2. `userId != null` 时 `total += repository.deleteByUserId(userId)`。
3. `total += repository.deleteByTarget(empNo)`。
4. 若 `byName && name != null && !name.contains("%") && !name.contains("_")`：
   `total += repository.deleteByActionAndTargetLike(OpAction.UPDATE_SCHEDULE, name + " %")`；
   `total += repository.deleteByActionAndDetail(OpAction.SET_DUTY_PHONE, name)`。
5. 返回 `total`。本方法自己**不记**任何日志。

**验收标准**（`OpLogServiceTest` 新增，Mockito 打桩 `repository`，各删除方法打桩返回 1）

| 输入 `purgeStaff(...)` | 期望 |
|---|---|
| `(7L, "A01", "张三", true)` | 返回 4；依次调用 `deleteByUserId(7L)`、`deleteByTarget("A01")`、`deleteByActionAndTargetLike("修改排班", "张三 %")`、`deleteByActionAndDetail("设置值班电话", "张三")` |
| `(null, "A01", "张三", true)` | 返回 3；`deleteByUserId` 未被调用 |
| `(7L, "A01", "张三", false)` | 返回 2；两个按姓名的方法都未被调用 |
| `(7L, "A01", "张_三", true)` | 返回 2；两个按姓名的方法都未被调用 |

**规模**：约 60 行。**依赖**：无。

## M5-04 实现人员导入文件的解析与校验

**背景**：批量导入的第一步，把 xlsx 解析成行并做全部“不查库”的校验（§9.5）。纯函数，便于单测；M5-12 调用。

**允许修改的文件**（全部新建）
- `backend/src/main/java/com/hospital/pbb/staff/StaffImportParser.java`
- `backend/src/main/java/com/hospital/pbb/staff/dto/StaffImportRow.java`
- `backend/src/main/java/com/hospital/pbb/staff/dto/StaffImportParseResult.java`
- `backend/src/test/java/com/hospital/pbb/staff/StaffImportParserTest.java`

**禁止修改**：`StaffService.java`、`StaffController.java`、`pom.xml`（`poi-ooxml` 已在依赖里）。

**接口定义**

```java
package com.hospital.pbb.staff.dto;
/** 一行导入数据。rowNo = Excel 行号（表头是第 1 行）；role 为 null 表示“角色”列为空 */
public record StaffImportRow(int rowNo, String empNo, String name, String position, String phone,
                             boolean schedulable, Role role) {}
/** errors 非空时 rows 不可用 */
public record StaffImportParseResult(List<StaffImportRow> rows, List<String> errors) {}

package com.hospital.pbb.staff;
public final class StaffImportParser {
    public static final List<String> HEADERS = List.of("工号", "姓名", "岗位", "联系电话", "参与排班", "角色");
    public static final int MAX_ROWS = 500;
    private StaffImportParser() {}
    public static StaffImportParseResult parse(InputStream in)
}
```

**实现要点**
1. `WorkbookFactory.create(in)`；抛任何异常 → 返回错误 `文件无法读取，请使用【批量导出】得到的 xlsx 文件`。
2. 取第 0 个 sheet，用 `new DataFormatter()` 的 `formatCellValue(cell)` 取文本并 `trim()`；`null` 单元格当空串。
3. 第 0 行 6 个单元格文本 ≠ `HEADERS` → 错误 `表头应为：工号、姓名、岗位、联系电话、参与排班、角色`，直接返回。
4. 从第 1 行到 `getLastRowNum()`：6 列全空跳过；其余按下表逐列校验，同一行可以有多条错误。
5. 岗位、联系电话为空串时存 `null`；参与排班 空/是 → true，否 → false；角色 空 → null，科长 → `ADMIN`，成员 → `MEMBER`。
6. 文件内工号重复：后出现的行报 `第{n}行：工号 {empNo} 与第{m}行重复`。
7. 有效数据行 0 行 → `文件里没有人员数据`；超过 `MAX_ROWS` → `一次最多导入 500 人`。
8. 错误信息里**不得出现手机号**。

| 列 | 规则 | 错误信息 |
|---|---|---|
| 工号 | 必填，`^[A-Za-z0-9_]{3,32}$` | `第{n}行：工号应为 3-32 位字母、数字或下划线` |
| 姓名 | 必填 | `第{n}行：姓名不能为空` |
| 姓名 | ≤ 32 字 | `第{n}行：姓名不能超过 32 个字` |
| 岗位 | ≤ 32 字 | `第{n}行：岗位不能超过 32 个字` |
| 联系电话 | ≤ 32 字 | `第{n}行：联系电话不能超过 32 个字` |
| 参与排班 | 空 / 是 / 否 | `第{n}行：参与排班只能填“是”或“否”` |
| 角色 | 空 / 科长 / 成员 | `第{n}行：角色只能填“科长”或“成员”` |

**验收标准**（测试里用 `XSSFWorkbook` 在内存造文件，写到 `ByteArrayOutputStream` 再传入）

| 输入 | 期望 |
|---|---|
| 表头 + `A01,张三,医生,13800000000,是,成员` + `A02,李四,,,否,` | errors 为空；2 行；第 2 行 rowNo=3、position=null、schedulable=false、role=null |
| 工号单元格是数字 `1001`（`setCellValue(1001)`） | empNo=`"1001"` |
| 表头第 3 列写成“职务” | errors=[`表头应为：工号、姓名、岗位、联系电话、参与排班、角色`] |
| 第 2 行姓名空 | errors 含 `第2行：姓名不能为空` |
| 第 2、4 行工号都是 `A01` | errors 含 `第4行：工号 A01 与第2行重复` |
| 第 2 行参与排班=“Y” | errors 含 `第2行：参与排班只能填“是”或“否”` |
| 只有表头 + 一行 6 列全空 | errors=[`文件里没有人员数据`] |
| 501 行合法数据 | errors 含 `一次最多导入 500 人` |
| 传入 `"not excel".getBytes()` | errors=[`文件无法读取，请使用【批量导出】得到的 xlsx 文件`] |
| 第 2 行手机号 `13800000000`、角色=“主任” | 所有 errors 拼接后不含 `13800000000` |

**规模**：约 180 行（含测试）。**依赖**：无。

## M5-05 新增删除人员接口封装与上传下载工具

**背景**：前端地基，供 M5-10、M5-13 使用。导入接口成功时返回文件、失败时返回 JSON，需要一个新的上传工具。

**允许修改的文件**

- `frontend/src/api/download.js`
- `frontend/tests/download.test.js`（新建）

**禁止修改**：任何 `views/*.vue`、`api/http.js`。

**接口定义**

```js
// api/staff.js 新增
export const deleteStaff = (id) => http.delete(`/staff/${id}`)

// api/download.js
// 现有 download(url, params, filename) 行为不变，只把“生成 <a> 触发保存”的几行抽成内部函数 saveBlob(blob, filename)
// 新增：以 multipart 上传一个文件，成功时把响应文件存下来并返回 true；任何失败弹提示并返回 false
export async function uploadForFile(url, file, filename)
```

**实现要点**
1. 抽出 `function saveBlob(blob, filename)`（不导出），`download` 改为调用它。
2. `uploadForFile`：`const form = new FormData(); form.append('file', file)`；`axios.post('/api' + url, form, { responseType: 'blob', headers: { Authorization: 'Bearer ' + localStorage.getItem('pbb_token') } })`。
3. 请求抛错 → `ElMessage.error('上传失败')`，返回 `false`。
4. 响应 `content-type` 含 `application/json` → 解析 `await resp.data.text()`，`ElMessage.error(body.message || '上传失败')`，返回 `false`（解析失败也提示“上传失败”）。
5. 否则 `saveBlob(resp.data, filename)`，返回 `true`。

**验收标准**（`download.test.js`，`vi.mock('axios')`、`vi.mock('element-plus')` 打桩 `ElMessage.error`；`URL.createObjectURL`/`revokeObjectURL` 用 `vi.fn` 打桩）

| 场景 | 期望 |
|---|---|
| `axios.post` 返回 `{ headers: {'content-type':'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet'}, data: new Blob(['x']) }` | 返回 `true`；`URL.createObjectURL` 被调用 1 次；`axios.post` 第 1 个参数为 `'/api/staff/import'`，第 2 个参数是 `FormData` 且 `get('file')` 为传入文件 |
| 返回 `{ headers: {'content-type':'application/json'}, data: new Blob([JSON.stringify({code:1210,message:'导入失败，没有写入任何数据：第2行：姓名不能为空'})]) }` | 返回 `false`；`ElMessage.error` 以该 message 调用 |
| `axios.post` reject | 返回 `false`；`ElMessage.error('上传失败')` |
| `download('/x', null, 'a.xlsx')`，`axios.get` 返回文件 | `URL.createObjectURL` 被调用 1 次（原行为不变） |

**规模**：约 90 行（含测试）。**依赖**：无。
