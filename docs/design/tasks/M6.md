## M6-01 把统计报表的值班电话从按天改为按周

**背景**：需求方要求统计每人每月排了几周值班电话（§10.1 第 5、6 条）。跨月的一周算在周四所在的月份。本单把后端字段 `dutyPhoneDays` 改名为 `dutyPhoneWeeks` 并改口径，同时修改统计页和冒烟脚本里用到这个字段的地方。

**允许修改的文件**
- `backend/src/main/java/com/hospital/pbb/stats/dto/StatsRowVO.java`
- `backend/src/main/java/com/hospital/pbb/stats/StatsService.java`
- `backend/src/test/java/com/hospital/pbb/stats/StatsServiceTest.java`
- `frontend/src/views/StatsView.vue`
- `scripts/smoke-test.sh`（只改步骤 8 里读值班电话的那 3 行）

**禁止修改**：`DutyPhonePublishedRepository.java`、`StatsController.java`、schedule 包下任何文件、任何迁移脚本、`ScheduleView.vue`。

**接口定义**

```java
/**
 * ...（前面的 @param 不变）
 * @param dutyPhoneWeeks 值班电话周数：已发布值班电话周中，周四落在统计区间内的周数（跨月的周算在天数多的月）
 */
public record StatsRowVO(Long staffId, String empNo, String name, Map<String, Integer> counts,
                         int offDayWork, BigDecimal totalHours, int dutyPhoneWeeks) {}

// StatsService：删除 dutyPhoneDays(from, to)，换成
private Map<Long, Integer> dutyPhoneWeeks(LocalDate from, LocalDate to);
```

**实现要点**
1. `StatsRowVO`：最后一个字段 `dutyPhoneDays` 改名为 `dutyPhoneWeeks`，并按上面的接口定义改写注释。
2. `StatsService.dutyPhoneWeeks(from, to)`：
   - 调用 `dutyPublishedRepo.findByWeekStartBetweenOrderByWeekStartAsc(from.minusDays(3), to.minusDays(3))`。
   - 对每行计算 `LocalDate thursday = row.getWeekStart().plusDays(3)`。只有 `!thursday.isBefore(from) && !thursday.isAfter(to)` 时，才执行 `weeks.merge(row.getStaffId(), 1, Integer::sum)`。
   - 方法注释写明：周四所在月就是这一周天数多的那个月，所以整月、整季度、全年统计时每周恰好算一次。
3. `stats()` 里的局部变量和调用改为 `dutyPhoneWeeks`；`rowOf` 的参数名改为 `dutyPhoneWeeks`。
4. `exportHeaders()`：`"值班电话（天）"` 改为 `"值班电话（周）"`；`exportRows()` 改为 `row.dutyPhoneWeeks()`。类中注释里出现的“值班电话（天）”一并改为“值班电话（周）”。
5. `StatsView.vue`：列 `label` 改为 `值班电话（周）`；`row.dutyPhoneDays` 改为 `row.dutyPhoneWeeks`，表格列和合计行两处都要改；合计行上方的注释同步修改。
6. `scripts/smoke-test.sh` 步骤 8：
   ```bash
   # M6：甲值班的 ${FIRST_MON} 那一周整周都在 ${NM} 内，值班电话周数必然是 1
   DUTY_WEEKS="$(printf '%s' "$STATS" | jpick data.rows staffId "$SID_A" dutyPhoneWeeks)"
   [ "$DUTY_WEEKS" = "1" ] || fail "甲的 dutyPhoneWeeks 应为 1，实际 ${DUTY_WEEKS:-空}"
   ```
7. `StatsServiceTest`：把方法名和断言里的 `dutyPhoneDays` 全部换成 `dutyPhoneWeeks`，期望值按下表改写；再新增用例 G、H、I。测试类里 `FROM=2026-10-01`、`TO=2026-10-31`。

**验收标准**（`StatsServiceTest`，`dutyPhones(...)` 是现有的打桩方法）

| 用例 | 输入 | 期望 |
|---|---|---|
| A（改） | 张三值 `2026-09-28` 那一周，统计 FROM~TO | `dutyPhoneWeeks = 1`（周四 10-01 在 10 月） |
| B（改） | 张三值 `2026-10-05`、`2026-10-12` | `2` |
| C（改） | 张三值 `2026-10-26` 那一周 | `1`（周四 10-29 在 10 月） |
| D（改） | 没有值班电话 | `0` |
| 按人（改） | 李四值 `2026-10-05` | 张三 `0`，李四 `1` |
| 成员 E（改） | 张三值 `2026-09-28`、李四值 `2026-10-05`，以成员身份统计 | 只有本人一行，`1` |
| 查询范围（改） | 统计 FROM~TO | 断言仓库被调用为 `findByWeekStartBetweenOrderByWeekStartAsc(2026-09-28, 2026-10-28)`；方法名改为 `dutyPhoneQueryCoversWeeksWhoseThursdayIsInRange` |

| 导出表头（改） | `exportHeaders()` | 倒数第二列 `值班电话（周）`，共 11 列 |
| 导出行（改） | 现有用例 `exportRowsMatchHeadersAndEveryRowHasElevenCells` | 李四一行改为 `List.of("B002", "李四", 0, 0, 0, 0, 0, 0, 0, 1, new BigDecimal("0"))` |

另外还要满足：
- `cd backend && mvn test` 全部通过。

## M6-02 在排班表格子弹窗里增加「值班电话」开关

**背景**：科长希望点格子时，就能顺手把这个人设为当周的值班电话负责人，也能取消（§10.1 第 1～4 条）。值班电话仍然按周安排，本单只在弹窗里加一个开关，写入现有的待暂存值班电话 `pendingDuty`，后端不改。

**允许修改的文件**
- `frontend/src/views/ScheduleView.vue`
- `frontend/tests/ScheduleView.pending.test.js`（只在文件末尾新增一个 `describe`，不改现有用例）

**禁止修改**：`frontend/src/api/*`、`StatsView.vue`、任何后端文件；不得修改 `setDuty`、`saveDraftNow`、`dropPending`、`clearPending` 的现有逻辑。

**接口定义**（`ScheduleView.vue` `<script setup>` 新增）

```js
// 弹窗这一格所在的周（weeks 中 weekStart ≤ editDate ≤ weekEnd 的那一项），找不到为 null
const editWeek = computed(() =>
  weeks.value.find((w) => w.weekStart <= editDate.value && editDate.value <= w.weekEnd) || null
)
const dutyPick = ref(false)     // 弹窗里「值班电话」开关当前值
const openDuty = ref(false)     // 打开弹窗时的开关值
const openPick = ref(DEFAULT_PICK) // 打开弹窗时的班次
const openRemark = ref('')      // 打开弹窗时的备注
```

**实现要点**
1. 模板：在 `恢复规则默认` 按钮之后、`</div>`（`.opts` 结束）之前加入下面的按钮：
   ```html
   <button
     v-if="editWeek"
     type="button"
     class="opt duty-opt"
     :class="{ on: dutyPick }"
     :style="dutyPick ? { background: data?.dutyPhoneColor } : null"
     @click="dutyPick = !dutyPick"
   >值班电话</button>
   ```
   在 `.opts` 之后、备注输入框之前加一行提示：`<div v-if="editWeek" class="duty-tip">值班电话按周安排：{{ editWeek.label }} 整周</div>`。
2. 样式：`.opt.duty-opt { background: #fff; border: 1px solid #d1d5db; color: #111827; }`、`.duty-tip { margin-top: 8px; color: #6b7280; font-size: 12px; }`。**不要用 `.duty` 这个类名**，它已经被表格上方的值班电话行占用了。
3. `openEditor`：在给 `pick`、`remark` 赋值之后，加上：
   ```js
   openPick.value = pick.value
   openRemark.value = remark.value
   const week = weeks.value.find((w) => w.weekStart <= date && date <= w.weekEnd)
   openDuty.value = !!week && dutyByWeek.value[week.weekStart] === row.staffId
   dutyPick.value = openDuty.value
   ```
4. `confirmPick`：保留原有的前置判断（`loading`、`staffId`/`workDate`/`editYm` 检查、`clearPending` 兜底），把原来写 `pendingCells` 的代码改成下面这样：
   ```js
   const dutyChanged = !!editWeek.value && dutyPick.value !== openDuty.value
   const cellChanged = pick.value !== openPick.value || remark.value.trim() !== openRemark.value.trim()
   // 只动了值班电话开关：不写这一格，免得没改班次的格子也变成“手工修改”
   if (!dutyChanged || cellChanged) {
     pendingCells.value = { ...原来的写法不变... }
   }
   if (dutyChanged) {
     const weekStart = editWeek.value.weekStart
     const prev = dutyByWeek.value[weekStart]
     if (dutyPick.value && prev !== undefined && prev !== null && prev !== staffId) {
       ElMessage.info(`已替换原值班电话负责人 ${dutyName(weekStart)}`)
     }
     pendingDuty.value = { ...pendingDuty.value, [weekStart]: dutyPick.value ? staffId : null }
   }
   pendingYm.value = editYm.value
   editorVisible.value = false
   ```
   注意：`dutyName(weekStart)` 必须在修改 `pendingDuty` **之前**调用，这样取到的才是原负责人的姓名。
5. 在 `ScheduleView.pending.test.js` 末尾新增 `describe('M6-02 弹窗设置值班电话', ...)`，复用现有的 `mountDuty`、`dutyMonthOf`、`dutyRow`、`dutyRowTds`、`dayCol`、`dutyBg`、`DUTY_YELLOW`、`btnByText`、`click`、`dutySelects`。打开张三某天的格子用 `await click(dutyRowTds(wrapper, 0)[dayCol(日)])`。
