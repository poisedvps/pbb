错误码：1800 排班周期模板不存在；1801 模板名称已存在；1802 默认模板不能删除；1803 模板中的班次不存在或已停用；1804 至少保留一个默认模板。

**实现要点**
1. `list`：`repo.findAllByOrderByIdAsc()` 转 VO。
2. 共用校验：`name.trim()` 后查重（create 用 `existsByName`，update 用 `existsByNameAndIdNot`）→ 1801；7 个代号逐个 `shiftRepo.findById(code).filter(ShiftType::isEnabled)`，任一不存在 → 1803。
3. `create`：`isDefault=true` 时先把当前默认模板（`findFirstByDefaultTemplateTrue`）改为 false 并 `saveAndFlush`，再保存新模板（部分唯一索引要求先取消旧默认）。
4. `update`：找不到 → 1800；当前是默认且请求 `isDefault=false` → 1804；请求 `isDefault=true` 且当前不是默认时同第 3 步处理旧默认；更新 name、days、`updatedAt=OffsetDateTime.now(clock)`。
5. `delete`：找不到 → 1800；是默认模板 → 1802；否则删除（`schedule_month.cycle_template_id` 由外键自动置空）。
6. 三个写操作各记一条日志：`CREATE_CYCLE` / `UPDATE_CYCLE` / `DELETE_CYCLE`，target=模板名，detail=`周一至周日：D D D D D X X`（delete 的 detail 为空串）。

**验收标准**

| 用例 | 期望 |
|---|---|
| create `{name:"夜班周期", days:[N,X,D,D,D,X,X], isDefault:false}` | 返回 id、isDefault=false，记一条日志 |
| create 同名“标准周期” | 1801 |
| create days 含 `"Q"` 或含已停用班次 | 1803 |
| create `isDefault:true` | 原默认模板被置为 false 且先于新模板保存 |
| update 默认模板为 `isDefault:false` | 1804 |
| update 不存在的 id / delete 不存在的 id | 1800 |
| delete 默认模板 | 1802 |
| curl：成员调 `GET /api/cycle-templates` | HTTP 403 |
| curl：`days` 只有 6 个元素 | `code=400` |

**规模**：约 190 行（含测试）。**依赖**：M4-01、M4-02。

**接口定义**

```java
// RuleCalendar
/**
 * 按周期模板取默认班次：调休上班日 → D；放假日 → X；其余日子 → days.get(星期几 - 1)。
 * @param days 7 个班次代号（下标 0=周一），为 null 时等同 defaultShift(date)
 */
public String defaultShift(LocalDate date, List<String> days);

// ScheduleService
/**
 * @param templateId 周期模板 id；null 表示用默认模板，没有默认模板时用内置规则
 * @throws BizException 1507 模板不存在；1502 模板中的班次不存在或已停用
 */
@Transactional public GenerateResultVO generate(String yearMonth, Long templateId, Long operatorId);

/** 该月记录的模板的 7 天班次；月份无记录、未记录模板或模板已删除时返回 null */
private List<String> templateDaysOf(String yearMonth);

// ScheduleController
@PostMapping("/{yearMonth}/generate") @PreAuthorize("hasRole('ADMIN')")
public ApiResponse<GenerateResultVO> generate(@PathVariable String yearMonth,
        @RequestParam(required = false) Long templateId, @AuthenticationPrincipal AuthUser me);
```

**实现要点**
1. `RuleCalendar.defaultShift(date, days)`：`days == null` 返回 `defaultShift(date)`；`kindOf(date)` 为 `ADJUSTED_WORKDAY` 返回 `"D"`，为 `HOLIDAY` 返回 `"X"`；否则返回 `days.get(date.getDayOfWeek().getValue() - 1)`。
2. `generate` 在取锁之后解析模板：`templateId != null` 时 `templateRepo.findById`，不存在抛 `BizException(1507, "排班周期模板不存在")`；为 null 时 `templateRepo.findFirstByDefaultTemplateTrue().orElse(null)`。
3. 模板不为 null 时，对 `template.days()` 去重后逐个 `shiftRepo.findById(code).filter(ShiftType::isEnabled)`，任一不满足抛 1502。
4. 循环里把 `calendar.defaultShift(date)` 换成 `calendar.defaultShift(date, days)`（`days = template == null ? null : template.days()`）。

7. `updateEntry` 中 `shiftCode == null` 分支改为 `calendar.defaultShift(workDate, templateDaysOf(yearMonth))`。

**背景**：需求方要求“暂存”：科长在页面上批量修改，点【暂存】一次性保存全部格子与值班电话（设计 §8.5“暂存”）。

- `backend/src/main/java/com/hospital/pbb/schedule/ScheduleService.java`（新增 `saveDraft`；可把 `updateEntry` 的写格子部分抽成私有方法供两处共用）

**禁止修改**：`generate`、`publish`、`applyChanges` 的逻辑。

**接口定义**

```java
public record DutyPhoneChange(@NotNull LocalDate weekStart, Long staffId) {}   // staffId=null 表示清除该周
public record SaveDraftRequest(@NotNull @Size(max = 2000) List<@Valid UpdateEntryRequest> entries,
                               @NotNull @Size(max = 6) List<@Valid DutyPhoneChange> dutyPhones) {}
public record SaveDraftResultVO(int entries, int dutyPhones) {}

// ScheduleService
/**
 * 暂存：先校验全部，再加锁写入；任何一条不合法都不写。
 * @throws BizException 1500/1501/1502/1503/1505/1506
 */
@Transactional public SaveDraftResultVO saveDraft(String yearMonth, SaveDraftRequest req, Long operatorId);

// ScheduleController
@PutMapping("/{yearMonth}/draft") @PreAuthorize("hasRole('ADMIN')")
public ApiResponse<SaveDraftResultVO> saveDraft(@PathVariable String yearMonth,
        @Valid @RequestBody SaveDraftRequest req, @AuthenticationPrincipal AuthUser me);
```

**实现要点**
1. `ym = ScheduleMonths.parse(yearMonth)`。
2. 校验每个格子：日期不在该月 → 1503；人员不存在或非 active/schedulable → 1501；`shiftCode` 非 null 且班次不存在或停用 → 1502。
3. 校验每个值班电话：`weekStart` 不是周一 → `BizException(1505, "值班电话的周起始日必须是周一")`；`weekStart.plusDays(6)` 早于月初或 `weekStart` 晚于月末 → `BizException(1506, "该周与本月没有交集")`；`staffId` 非 null 且人员无效 → 1501。
4. 收集月份：`ym` 加上每周的 `ScheduleMonths.monthsOfWeek(weekStart)`，去重升序后逐个 `monthRepo.lockMonth(ScheduleMonths.lockKey(m))`。
5. 逐格写入：与 `updateEntry` 取锁之后的写法完全相同（`shiftCode=null` 按 `templateDaysOf` 重算、manual=false；否则 manual=true；每格一条 `UPDATE_SCHEDULE` 日志），但**不**单独 `markDraft`。
6. 逐周写值班电话：`staffId=null` 时 `dutyRepo.deleteById(weekStart)`（存在才删）；否则取已有或新建 `DutyPhoneWeek`，设 staffId、updatedBy、updatedAt 后保存。每周记 `SET_DUTY_PHONE`，target=`值班电话 MM-dd 周`（weekStart 格式化），detail=姓名或 `清除`。
7. 对第 4 步收集到的每个月 `markDraft`。
8. 记 `SAVE_DRAFT`，target=yearMonth，detail=`{entries.size()}格，值班电话{dutyPhones.size()}周`；返回 `SaveDraftResultVO`。

**验收标准**

| 用例 | 期望 |
|---|---|
| 2 个格子 + 1 周（2026-10-05，张三） | 两格保存、manual=true；`duty_phone_week` 保存 10-05/张三；10 月 DRAFT；返回 `{2,1}` |
| 1 个格子 shiftCode=null，该月 cycleTemplateId 指向全 N 模板 | 该格为 N、manual=false |
| 第 2 个格子日期是 11-01 | 1503，**第 1 个格子也没有保存**（`entryRepo.save` 从未调用） |
| 值班电话 weekStart=2026-10-06（周二） | 1505 |
| weekStart=2026-11-02 | 1506 |
| weekStart=2026-09-28 | 依次 `lockMonth(202609)`、`lockMonth(202610)`；9 月和 10 月都 markDraft |
| weekStart=2026-10-05，staffId=null，库里已有该周 | 该周被删除，日志 detail 为“清除” |
| staffId 为停用人员 | 1501 |
| curl：`entries` 2001 条 | `code=400` |
| curl：成员调用 | HTTP 403 |

**规模**：约 190 行（含测试）。**依赖**：M4-05。

**背景**：需求方选择方案 A：格子修改先留在页面上，点【暂存】才一次性保存（设计 §8.1 第 1 条）。本单只做格子的暂存，值班电话在 M4-15 接入同一个暂存机制。

**实现要点**
1. 编辑弹窗的【保存】改名为【确定】：不再调 `updateEntry`，而是写入 `pendingCells`（同一格再次修改覆盖）并关闭弹窗。选“恢复规则默认”时 `shiftCode=null`。
2. 显示：有待暂存修改的格子 `td` 加 class `pending`（`outline: 2px dashed #f59e0b; outline-offset: -2px;`）；色块按待暂存的班次显示；`shiftCode=null` 时显示灰色文字“默认”。再次打开该格时弹窗预选待暂存的值。

7. 顶部状态标签：N>0 时追加一个 `el-tag type="danger"` “有 N 处未暂存”。
8. 页脚提示文字改为“点击单元格修改班次，修改后点【暂存】保存；底部行 = 每日在岗人数”。

**实现要点**
