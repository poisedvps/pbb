### 通用约定（每张任务单都适用）

1. **分支**：从最新 `main` 拉分支 `m2-XX-<英文短名>`，完成后提 PR 到 `main`。
2. **开发环境**：只用本机 Docker Compose 启动的测试库。复制 `.env.example` 为 `.env`，自行填写测试用的随机值（`PBB_JWT_SECRET` 至少 32 个字符）。**`.env` 禁止提交。**
3. **启动**：`docker compose up -d --build`，访问 `http://localhost:8090`；初始管理员 `admin/admin`，首次登录需改密。
4. **后端测试**（本机没有 Maven 时用容器跑）：
   ```bash
   docker run --rm -v "$PWD/backend":/src -w /src maven:3.9-eclipse-temurin-17 mvn -s settings.xml -q test
   ```
5. **前端检查**：`cd frontend && npm install && npm run build` 必须成功。
6. **返回体**：Controller 一律返回 `ApiResponse.ok(data)`；业务错误抛 `new BizException(code, message)`，错误码见 architecture §5.1。
7. **日志**：禁止在日志、操作日志、异常信息里输出密码、token、完整手机号。操作日志动作名一律用 `OpAction` 常量。
8. **不得修改**：`V1__init_schema.sql`、`docker-compose.yml`、`.env.example`、`scripts/**`、`docs/**`，以及任务单“允许修改的文件”之外的任何文件。
9. **当前时间**一律从注入的 `java.time.Clock` 取（`LocalDate.now(clock)`、`OffsetDateTime.now(clock)`），不要直接调 `LocalDate.now()`。
10. **模块边界**：只有 `schedule` 包里的类可以写 `schedule_month`、`schedule_entry`、`schedule_published_entry`。其他模块只读别的模块时，可以直接用对方 Repository 的查询方法。
11. **curl 验收**里的 `$TOKEN`（科长）、`$MTOKEN`（成员）、`$STOKEN`（大屏账号）是 shell 变量，由执行者在本机登录后设置，不要写进代码或提交。

## M2-01 新增排班实体与仓库

**背景**：排班模块的数据层。三张表 `schedule_month`、`schedule_entry`、`schedule_published_entry` 在 V1 迁移里已经建好，本单只写 JPA 实体和仓库。

**允许修改的文件**（全部新建）

- `backend/src/main/java/com/hospital/pbb/schedule/ScheduleMonth.java`
- `backend/src/main/java/com/hospital/pbb/schedule/ScheduleEntry.java`
- `backend/src/main/java/com/hospital/pbb/schedule/SchedulePublishedEntry.java`
- `backend/src/main/java/com/hospital/pbb/schedule/ScheduleMonthRepository.java`
- `backend/src/main/java/com/hospital/pbb/schedule/ScheduleEntryRepository.java`

**禁止修改**：`V1__init_schema.sql`、`application.yml`（`ddl-auto: validate` 不能改）。

**接口定义**

```java
package com.hospital.pbb.schedule;

public enum ScheduleStatus { DRAFT, PUBLISHED }

@Entity @Table(name = "schedule_month")
public class ScheduleMonth {
    // year_month 在库里是 CHAR(7)，必须加 @JdbcTypeCode(SqlTypes.CHAR)，否则 validate 启动失败
    @Id @JdbcTypeCode(SqlTypes.CHAR) @Column(name = "year_month", length = 7) private String yearMonth;
    @Enumerated(EnumType.STRING) @Column(nullable = false, length = 16) private ScheduleStatus status = ScheduleStatus.DRAFT;
    @Column(nullable = false) private int version = 0;
    @Column(name = "published_at") private OffsetDateTime publishedAt;
    @Column(name = "published_by") private Long publishedBy;
    // 所有字段的 getter / setter
}

@Entity @Table(name = "schedule_entry")
public class ScheduleEntry {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;
    @Column(name = "staff_id", nullable = false) private Long staffId;
    @Column(name = "work_date", nullable = false) private LocalDate workDate;
    @Column(name = "shift_code", nullable = false, length = 4) private String shiftCode;
    @Column(name = "is_manual", nullable = false) private boolean manual;
    @Column(length = 200) private String remark;
    @Column(name = "updated_by") private Long updatedBy;
    @Column(name = "updated_at", nullable = false) private OffsetDateTime updatedAt = OffsetDateTime.now();
    // 所有字段的 getter / setter（boolean 用 isManual / setManual）
}

@Entity @Table(name = "schedule_published_entry")
public class SchedulePublishedEntry {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;
    @Column(name = "staff_id", nullable = false) private Long staffId;
    @Column(name = "work_date", nullable = false) private LocalDate workDate;
    @Column(name = "shift_code", nullable = false, length = 4) private String shiftCode;
    @Column(length = 200) private String remark;
    @Column(nullable = false) private int version;
    // 所有字段的 getter / setter
}

public interface ScheduleMonthRepository extends JpaRepository<ScheduleMonth, String> {
    /** 按月取事务级锁，key = 年*100+月（如 202610）；号段 1500 专用于排班 */
    @Query(value = "select pg_advisory_xact_lock(1500, :key)", nativeQuery = true)
    void lockMonth(@Param("key") int key);
}

public interface ScheduleEntryRepository extends JpaRepository<ScheduleEntry, Long> {
    List<ScheduleEntry> findByWorkDateBetween(LocalDate start, LocalDate end);
    Optional<ScheduleEntry> findByStaffIdAndWorkDate(Long staffId, LocalDate workDate);
}

public interface SchedulePublishedEntryRepository extends JpaRepository<SchedulePublishedEntry, Long> {
    List<SchedulePublishedEntry> findByWorkDateBetween(LocalDate start, LocalDate end);
    List<SchedulePublishedEntry> findByStaffIdAndWorkDateBetweenOrderByWorkDateAsc(Long staffId, LocalDate start, LocalDate end);
    Optional<SchedulePublishedEntry> findByStaffIdAndWorkDate(Long staffId, LocalDate workDate);
    @Modifying @Query("delete from SchedulePublishedEntry e where e.workDate between :start and :end")
    int deleteByWorkDateRange(@Param("start") LocalDate start, @Param("end") LocalDate end);
}
```

**实现要点**
1. 按上面的代码逐个新建文件，包名为 `com.hospital.pbb.schedule`。
2. `@JdbcTypeCode` 来自 `org.hibernate.annotations.JdbcTypeCode`，`SqlTypes` 来自 `org.hibernate.type.SqlTypes`。
3. 不写任何 Service、Controller。

**验收标准**
- 后端测试命令全部通过（原有测试不受影响）。
- `docker compose up -d --build` 后 `docker compose logs backend` 中没有 `Schema-validation` 错误，且 `curl -s http://localhost:8090/api/health` 返回含 `"db":"ok"`。

**规模**：约 150 行。**依赖**：无。

## M2-02 新增规则日历、月份解析与操作日志动作

**背景**：规则生成、我的排班、大屏、统计都要判断“某天是工作日、周末、放假还是调休上班”，统一由 `RuleCalendar` 计算。同时一次性补齐 M2、M3 要用的操作日志动作名，避免后续多张单同时改 `OpAction`。

**允许修改的文件**
- `backend/src/main/java/com/hospital/pbb/schedule/DayKind.java`（新建）
- `backend/src/main/java/com/hospital/pbb/schedule/RuleCalendar.java`（新建）
- `backend/src/main/java/com/hospital/pbb/schedule/ScheduleMonths.java`（新建）
- `backend/src/main/java/com/hospital/pbb/oplog/OpAction.java`（只在末尾追加常量）
- `backend/src/test/java/com/hospital/pbb/schedule/RuleCalendarTest.java`（新建）

**禁止修改**：`holiday` 包下的所有文件。

**接口定义**

```java
package com.hospital.pbb.schedule;

/** WORKDAY=周一至周五；WEEKEND=周六日；HOLIDAY=放假；ADJUSTED_WORKDAY=调休上班 */
public enum DayKind { WORKDAY, WEEKEND, HOLIDAY, ADJUSTED_WORKDAY }

public class RuleCalendar {
    /** holidays 是覆盖要计算的日期范围的节假日记录（可来自 HolidayRepository.findOverlapping） */
    public RuleCalendar(List<Holiday> holidays);
    /** 优先级：WORKDAY 类型节假日 > HOLIDAY 类型节假日 > 周六日 > 工作日 */
    public DayKind kindOf(LocalDate date);
    /** 该日所属节假日记录的 name，没有则 null */
    public String holidayName(LocalDate date);
    /** WORKDAY、ADJUSTED_WORKDAY → "D"；WEEKEND、HOLIDAY → "X" */
    public String defaultShift(LocalDate date);
    /** WEEKEND 或 HOLIDAY 返回 true */
    public boolean isOffDay(LocalDate date);
}

public final class ScheduleMonths {
    /** 必须匹配 ^\d{4}-(0[1-9]|1[0-2])$，否则 BizException(1500, "月份格式应为 YYYY-MM") */
    public static YearMonth parse(String yearMonth);
    /** 202610 这样的整数，用于 ScheduleMonthRepository.lockMonth */
    public static int lockKey(YearMonth ym);   // ym.getYear() * 100 + ym.getMonthValue()
}
```

`OpAction.java` 末尾追加（原有常量不动）：

```java
public static final String UPDATE_SCHEDULE = "修改排班";
public static final String GENERATE_SCHEDULE = "按规则生成排班";
public static final String PUBLISH_SCHEDULE = "发布排班";
public static final String APPLY_SWAP_TO_SCHEDULE = "调班回写排班";
public static final String CREATE_SWAP = "发起调班";
public static final String CONFIRM_SWAP = "同意调班";
public static final String REJECT_SWAP_PEER = "拒绝调班";
public static final String CANCEL_SWAP = "撤销调班";
public static final String APPROVE_SWAP = "审批通过调班";
public static final String REJECT_SWAP = "审批驳回调班";
```

**实现要点**
1. 构造函数里把每条节假日展开成逐日的两个 `Map<LocalDate, String>`：`workdays`（type=WORKDAY）和 `holidays`（type=HOLIDAY），值为 name。
2. `kindOf`：在 `workdays` 里 → ADJUSTED_WORKDAY；否则在 `holidays` 里 → HOLIDAY；否则 `getDayOfWeek()` 为 SATURDAY/SUNDAY → WEEKEND；否则 WORKDAY。
3. `holidayName`：先查 `workdays` 再查 `holidays`，都没有返回 null。
4. `ScheduleMonths` 是工具类：私有构造函数，两个静态方法。

**验收标准** — `RuleCalendarTest`（纯 JUnit，不用 Spring）：

| 用例 | 期望 |
|---|---|
| 无节假日，2026-10-05（周一） | WORKDAY，默认 D，isOffDay=false |
| 无节假日，2026-10-10（周六） | WEEKEND，默认 X，isOffDay=true |
| 国庆节 HOLIDAY 2026-10-01~10-07，查 10-05 | HOLIDAY，默认 X，holidayName=国庆节 |
| 国庆调休 WORKDAY 2026-10-10~10-10，查 10-10 | ADJUSTED_WORKDAY，默认 D，holidayName=国庆调休 |
| `ScheduleMonths.parse("2026-10")` | `YearMonth.of(2026,10)` |
| `parse("2026-13")`、`parse("2026-1")`、`parse(null)` | 均抛 BizException，code=1500 |
| `lockKey(YearMonth.of(2026,10))` | 202610 |

**规模**：约 150 行。**依赖**：无。

## M2-03 实现排班月视图查询接口

**背景**：排班表页、大屏和导出都读“某个月的整张表”。科长读草稿（`schedule_entry`），其他角色读已发布快照（`schedule_published_entry`）。

**允许修改的文件**（全部新建）

- `backend/src/main/java/com/hospital/pbb/schedule/dto/StaffRowVO.java`
- `backend/src/main/java/com/hospital/pbb/schedule/dto/MonthScheduleVO.java`
- `backend/src/main/java/com/hospital/pbb/schedule/ScheduleQueryService.java`
- `backend/src/main/java/com/hospital/pbb/schedule/ScheduleController.java`
- `backend/src/test/java/com/hospital/pbb/schedule/ScheduleQueryServiceTest.java`

**禁止修改**：M2-01、M2-02 已有的文件；`staff`、`holiday`、`shift` 包。

**接口定义**

```java
package com.hospital.pbb.schedule.dto;

/** weekday：1=周一 … 7=周日 */
public record DayVO(LocalDate date, int weekday, DayKind kind, String holidayName) {}
/** manual 只有草稿才有意义，已发布数据一律 false */
public record CellVO(String shiftCode, boolean manual, String remark) {}
/** cells 的 key 是 "2026-10-01" 形式的日期字符串；没排班的日期不放进 map */
public record StaffRowVO(Long staffId, String empNo, String name, String position, Map<String, CellVO> cells) {}
/** draft=true 表示返回的是草稿 */
public record MonthScheduleVO(String yearMonth, ScheduleStatus status, int version, OffsetDateTime publishedAt,
                              boolean draft, List<DayVO> days, List<StaffRowVO> rows) {}

package com.hospital.pbb.schedule;

@Service
public class ScheduleQueryService {
    public ScheduleQueryService(ScheduleMonthRepository monthRepo, ScheduleEntryRepository entryRepo,
                                SchedulePublishedEntryRepository publishedRepo, StaffRepository staffRepo,
                                HolidayRepository holidayRepo);
    /** draft=true 读 schedule_entry，false 读 schedule_published_entry */
    public MonthScheduleVO getMonth(String yearMonth, boolean draft);
    /** 给本模块其它类和 screen、stats 复用：[start,end] 范围的规则日历 */
    public RuleCalendar calendar(LocalDate start, LocalDate end);
}

@RestController @RequestMapping("/api/schedules")
GET "/{yearMonth}"（登录即可）→ MonthScheduleVO
    // 参数 @AuthenticationPrincipal AuthUser me；draft = me.role() == Role.ADMIN
```

**实现要点**
1. `ym = ScheduleMonths.parse(yearMonth)`；`start = ym.atDay(1)`，`end = ym.atEndOfMonth()`。
2. `calendar(start, end)` = `new RuleCalendar(holidayRepo.findOverlapping(start, end))`。
3. `days`：从 start 到 end 逐日生成 DayVO，weekday 用 `date.getDayOfWeek().getValue()`，kind 和 holidayName 取自日历。
4. `rows`：`staffRepo.findByActiveTrueOrderBySortOrderAscIdAsc()` 中 `schedulable=true` 的人员，保持顺序。
5. 数据：draft 时 `entryRepo.findByWorkDateBetween(start,end)` → `CellVO(shiftCode, manual, remark)`；否则用 `publishedRepo.findByWorkDateBetween(start,end)` → `CellVO(shiftCode, false, remark)`。按 staffId 分组后放进各行的 cells（key = `workDate.toString()`）。cells 用 `LinkedHashMap`。
6. 月份状态：`monthRepo.findById(yearMonth)`，没有记录时 status=DRAFT、version=0、publishedAt=null。
7. Controller 的类上不加 `@PreAuthorize`（登录即可，大屏账号也能读已发布数据）。

- `ScheduleQueryServiceTest`（Mockito）：

| 2026-10，人员 A(schedulable) 和 B(schedulable=false)，无排班数据 | days 长度 31；rows 只有 A，cells 为空；status=DRAFT、version=0 |
| 10-01~10-07 国庆 HOLIDAY | days[0].kind=HOLIDAY，holidayName=国庆节 |
| draft=true，A 在 10-08 有草稿 N，manual=true | A.cells["2026-10-08"] = (N, true, null)；draft=true |
| draft=false，A 在 10-08 有已发布 D | A.cells["2026-10-08"] = (D, false, null)；不查草稿仓库 |

## M2-04 实现按规则生成与单元格修改接口

**背景**：科长先“按规则生成”整月默认班次，再逐格手工调整；手工格子标记 `is_manual`，再次生成时不会被覆盖。

**允许修改的文件**
- `backend/src/main/java/com/hospital/pbb/schedule/ScheduleService.java`（新建）
- `backend/src/main/java/com/hospital/pbb/schedule/dto/UpdateEntryRequest.java`（新建）
- `backend/src/main/java/com/hospital/pbb/schedule/dto/GenerateResultVO.java`（新建）
- `backend/src/main/java/com/hospital/pbb/schedule/ScheduleController.java`（只新增两个方法和构造参数）
- `backend/src/test/java/com/hospital/pbb/schedule/ScheduleServiceTest.java`（新建）

**禁止修改**：`ScheduleQueryService.java`、实体与仓库文件。

**接口定义**

```java
public record UpdateEntryRequest(@NotNull Long staffId, @NotNull LocalDate workDate,
                                 @Size(max = 4) String shiftCode,   // null = 恢复规则默认
                                 @Size(max = 200) String remark) {}
public record GenerateResultVO(int generated, int skippedManual) {}

@Service
public class ScheduleService {
    public ScheduleService(ScheduleMonthRepository monthRepo, ScheduleEntryRepository entryRepo,
                           SchedulePublishedEntryRepository publishedRepo, StaffRepository staffRepo,
                           ShiftTypeRepository shiftRepo, ScheduleQueryService query,
                           OpLogService opLog, Clock clock);
    @Transactional public GenerateResultVO generate(String yearMonth, Long operatorId);
    @Transactional public CellVO updateEntry(String yearMonth, UpdateEntryRequest req, Long operatorId);
}

// ScheduleController 新增（都加 @PreAuthorize("hasRole('ADMIN')")，operatorId 取 me.id()）
POST "/{yearMonth}/generate"                     → GenerateResultVO
PUT  "/{yearMonth}/entries"  body UpdateEntryRequest → CellVO
```

**实现要点**
1. 两个写方法开头都是：`ym = ScheduleMonths.parse(yearMonth)`，然后 `monthRepo.lockMonth(ScheduleMonths.lockKey(ym))`。
2. 私有方法 `markDraft(String yearMonth)`：`monthRepo.findById` 取不到就新建（status=DRAFT、version=0）；把 status 置为 DRAFT 后保存。
3. `generate`：`cal = query.calendar(start,end)`；人员取 `findByActiveTrueOrderBySortOrderAscIdAsc()` 中 schedulable 的；已有草稿 `entryRepo.findByWorkDateBetween` 转成 `Map<staffId+"|"+date, ScheduleEntry>`。
4. `generate` 逐人逐日：已有且 `isManual()` → skippedManual+1 后跳过；否则取已有或新建 entry，设 shiftCode=`cal.defaultShift(d)`、manual=false、updatedBy=operatorId、updatedAt=`OffsetDateTime.now(clock)`，保存，generated+1。
5. `generate` 最后 `markDraft`，记 `OpAction.GENERATE_SCHEDULE`（target=yearMonth，detail=`生成{generated}格，跳过手工{skippedManual}格`）。
6. `updateEntry`：workDate 不在该月 → 1503 `日期不在该月内`。
7. `updateEntry`：人员不存在、`!isActive()` 或 `!isSchedulable()` → 1501 `人员不存在或不参与排班`。
8. `updateEntry`：shiftCode 为 null → 用 `cal.defaultShift(workDate)`，manual=false；否则 `shiftRepo.findById(code)` 不存在或 `!isEnabled()` → 1502 `班次不存在或已停用`，manual=true。
9. `updateEntry`：取已有或新建 entry，写入 shiftCode、manual、remark（空串存 null）、updatedBy、updatedAt 并保存；`markDraft`。
10. `updateEntry` 记 `OpAction.UPDATE_SCHEDULE`：target=`{人员姓名} {MM-dd}`，detail=`{旧 code 或 空} → {新 code}`。返回 `CellVO(code, manual, remark)`。

**验收标准**
- `ScheduleServiceTest`（Mockito，`Clock.fixed(Instant.parse("2026-09-30T00:00:00Z"), ZoneId.of("Asia/Shanghai"))`）：

| 用例 | 期望 |
|---|---|
| generate 2026-10，1 名人员，无草稿、无节假日 | 返回 (31, 0)；10-05 保存为 D、10-10 保存为 X；月份状态为 DRAFT |
| generate 时该人 10-05 已有手工 N | 返回 (30, 1)；10-05 仍为 N |
| generate 前月份状态 PUBLISHED | 生成后为 DRAFT |
| updateEntry 10-05 改为 N | 返回 (N, true, null)；记日志 detail 为 `D → N` |
| updateEntry shiftCode=null | 返回规则默认，manual=false |
| updateEntry workDate=2026-11-01 | 1503 |
| updateEntry 人员 schedulable=false | 1501 |
| updateEntry shiftCode="Q" | 1502 |
| 任一写方法 | 先调用了 `lockMonth(202610)`（用 InOrder 验证在保存之前） |

- curl 验收：
  1. `curl -s -X POST -H "Authorization: Bearer $TOKEN" http://localhost:8090/api/schedules/2026-10/generate` → `code:0`，`data.generated` > 0
