## M3-01 新增调班回写排班的公开方法

**背景**：调班审批通过后要改排班，但只有 schedule 模块能写排班表（architecture §3 模块边界），所以由 schedule 提供公开方法给 swap 调用。

**允许修改的文件**
- `backend/src/main/java/com/hospital/pbb/schedule/dto/CellChange.java`（新建）
- `backend/src/main/java/com/hospital/pbb/schedule/ScheduleService.java`（只新增 `applyChanges`）
- `backend/src/main/java/com/hospital/pbb/schedule/ScheduleQueryService.java`（只新增 `publishedShift`）
- `backend/src/test/java/com/hospital/pbb/schedule/ScheduleServiceTest.java`（只新增用例）
- `backend/src/test/java/com/hospital/pbb/schedule/ScheduleQueryServiceTest.java`（只新增用例）

**接口定义**

```java
public record CellChange(Long staffId, LocalDate workDate, String shiftCode) {}

// ScheduleQueryService
/** 某人某天的已发布班次代码 */
public Optional<String> publishedShift(Long staffId, LocalDate date);

// ScheduleService
/**
 * 把调班结果同时写入草稿和已发布快照，不改变月份状态和版本号。
 * @param target 写入格子 remark 和操作日志 target，如 "调班 TB-0003"
 */
@Transactional public void applyChanges(List<CellChange> changes, String target, Long operatorId);
```

**实现要点**
1. `publishedShift`：`publishedRepo.findByStaffIdAndWorkDate(staffId, date).map(SchedulePublishedEntry::getShiftCode)`。
2. `applyChanges`：把 changes 涉及的月份（`YearMonth.from(workDate)`）去重、升序排列后，逐个 `lockMonth`。
3. 对每个 change 写草稿：取已有 entry 或新建，设 shiftCode、manual=true、remark=target、updatedBy=operatorId、updatedAt=now(clock)，然后保存。
4. 对每个 change 写已发布快照：`publishedRepo.findByStaffIdAndWorkDate` 存在时改 shiftCode、remark=target 并保存；不存在时跳过。
5. 不调用 `markDraft`，也不改 version。
6. 记一条 `OpAction.APPLY_SWAP_TO_SCHEDULE`：target=target，detail=`共{changes.size()}格`。

**验收标准**（新增单元测试）

| 用例 | 期望 |
|---|---|
| 2 条 change（A 10-08→X，B 10-08→N），两人都有草稿和已发布 | 草稿两格 manual=true、remark="调班 TB-0001"；已发布两格代码更新 |
| change 的格子没有已发布记录 | 只写草稿，不报错 |
| changes 跨 10 月和 11 月 | `lockMonth(202610)` 在 `lockMonth(202611)` 之前 |
| `publishedShift` 有记录 / 无记录 | `Optional.of("D")` / `Optional.empty()` |

**规模**：约 90 行。**依赖**：M2 全部。

```java
package com.hospital.pbb.swap;

/** SWAP=与同事换班；LEAVE=请假；COVER=替班（对方替我上） */
public enum SwapType { SWAP, LEAVE, COVER }
public enum SwapStatus { PENDING_PEER, PENDING_ADMIN, APPROVED, REJECTED, CANCELLED }

@Entity @Table(name = "swap_request")
public class SwapRequest {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;
    @Enumerated(EnumType.STRING) @Column(nullable = false, length = 16) private SwapType type;
    @Column(name = "applicant_staff_id", nullable = false) private Long applicantStaffId;
    @Column(name = "applicant_date", nullable = false) private LocalDate applicantDate;
    @Column(name = "target_staff_id") private Long targetStaffId;
    @Column(name = "target_date") private LocalDate targetDate;
    @Column(length = 200) private String reason;
    @Enumerated(EnumType.STRING) @Column(nullable = false, length = 16) private SwapStatus status;
    @Column(name = "peer_confirmed_at") private OffsetDateTime peerConfirmedAt;
    @Column(name = "reviewed_by") private Long reviewedBy;
    @Column(name = "reviewed_at") private OffsetDateTime reviewedAt;
    @Column(name = "review_comment", length = 200) private String reviewComment;
    @Column(name = "created_at", nullable = false, updatable = false) private OffsetDateTime createdAt = OffsetDateTime.now();
    // 所有字段的 getter / setter
}

public interface SwapRequestRepository extends JpaRepository<SwapRequest, Long> {
    List<SwapRequest> findAllByOrderByIdDesc();
    List<SwapRequest> findByApplicantStaffIdOrTargetStaffIdOrderByIdDesc(Long applicantStaffId, Long targetStaffId);
    List<SwapRequest> findByApplicantStaffIdOrderByIdDesc(Long applicantStaffId);
    List<SwapRequest> findByStatusOrderByIdDesc(SwapStatus status);
    List<SwapRequest> findByStatusAndTargetStaffIdOrderByIdDesc(SwapStatus status, Long targetStaffId);
    boolean existsByApplicantStaffIdAndApplicantDateAndStatusIn(Long staffId, LocalDate date, Collection<SwapStatus> statuses);
}
```

**实现要点**：按上面的代码逐个新建，不写 Service、Controller。

## M3-04 实现发起调班接口

**背景**：成员发起换班、请假、替班申请；请假不需要对方确认，直接进入科长审批。

**允许修改的文件**
- `backend/src/main/java/com/hospital/pbb/swap/dto/CreateSwapRequest.java`（新建）
- `backend/src/main/java/com/hospital/pbb/swap/SwapService.java`（只新增 `create`）
- `backend/src/main/java/com/hospital/pbb/swap/SwapController.java`（只新增 POST）
- `backend/src/test/java/com/hospital/pbb/swap/SwapServiceTest.java`（只新增用例）

**接口定义**

```java
public record CreateSwapRequest(@NotNull SwapType type, @NotNull LocalDate applicantDate,
                                Long targetStaffId, LocalDate targetDate, @Size(max = 200) String reason) {}

@Transactional public SwapVO create(CreateSwapRequest req, AuthUser me);

POST "" body CreateSwapRequest → SwapVO
```

**实现要点**（按顺序校验，先失败先返回）
1. `me.staffId()` 为 null → 1601 `当前账号未关联人员，不能申请调班`。
2. `today = LocalDate.now(clock)`；applicantDate 早于 today → 1603 `只能申请今天及以后的日期`。
3. LEAVE：忽略 targetStaffId、targetDate，都存 null。
4. SWAP、COVER：targetStaffId 为 null → 1606 `请选择对方人员`；等于自己 → 1604 `对方不能是自己`。
5. SWAP、COVER：对方人员不存在、`!isActive()` 或 `!isSchedulable()` → 1605 `对方人员不存在或不参与排班`。
6. SWAP：targetDate 为 null → 1606 `换班必须选择对方日期`；早于 today → 1603。COVER 的 targetDate 存 null。
7. 本人 applicantDate 没有已发布班次（`query.publishedShift`）→ 1602 `该日期没有已发布的班次`。
8. SWAP：本人@targetDate、对方@applicantDate、对方@targetDate 任一没有已发布班次 → 1602 `对方日期没有已发布的班次`。
9. COVER：对方@applicantDate 没有已发布班次 → 1602 `对方日期没有已发布的班次`。
10. `existsByApplicantStaffIdAndApplicantDateAndStatusIn(sid, applicantDate, [PENDING_PEER, PENDING_ADMIN])` → 1607 `该日期已有进行中的申请`。
11. 保存：status = LEAVE ? PENDING_ADMIN : PENDING_PEER；reason 空串存 null。
12. 记 `OpAction.CREATE_SWAP`：target=`TB-xxxx`，detail=`{type} {applicantDate}`。返回 `toVO`。

**验收标准**（Mockito，Clock 固定 2026-10-09）

| 用例 | 期望 |
|---|---|
| LEAVE 10-12，本人当天已发布 D | 保存 status=PENDING_ADMIN，target 均为 null |
| SWAP 10-12 ↔ 对方 10-13，四格都有已发布 | status=PENDING_PEER |
| staffId=null | 1601 |
| applicantDate=10-08 | 1603 |
| SWAP 对方=自己 | 1604 |
| SWAP 缺 targetDate | 1606 |
| 本人当天无已发布 | 1602 |
| 同一天已有 PENDING_PEER | 1607 |

- curl：成员 `POST /api/swaps {"type":"LEAVE","applicantDate":"<已发布月份内今天以后的日期>","reason":"事假"}` → `data.status=PENDING_ADMIN`。

**规模**：约 180 行。**依赖**：M3-03。

## M3-05 实现调班确认、拒绝、撤销与审批接口

**背景**：流程为“申请人发起 → 对方确认 → 科长审批 → 自动更新排班”，审批通过时按 architecture §5.3 计算要改的格子，调用 `ScheduleService.applyChanges`。

**允许修改的文件**
- `backend/src/main/java/com/hospital/pbb/swap/dto/ReviewRequest.java`（新建）
- `backend/src/main/java/com/hospital/pbb/swap/SwapService.java`（只新增 5 个方法和私有辅助方法）
- `backend/src/main/java/com/hospital/pbb/swap/SwapController.java`（只新增 5 个 POST）
- `backend/src/test/java/com/hospital/pbb/swap/SwapServiceTest.java`（只新增用例）

**接口定义**

```java
public record ReviewRequest(@Size(max = 200) String comment) {}

@Transactional public SwapVO confirm(Long id, AuthUser me);      // 对方同意
@Transactional public SwapVO rejectPeer(Long id, AuthUser me);   // 对方拒绝
@Transactional public SwapVO cancel(Long id, AuthUser me);       // 申请人撤销
@Transactional public SwapVO approve(Long id, String comment, AuthUser me);
@Transactional public SwapVO reject(Long id, String comment, AuthUser me);

POST "/{id}/confirm"                                     → SwapVO
POST "/{id}/reject-peer"                                 → SwapVO
POST "/{id}/cancel"                                      → SwapVO
POST "/{id}/approve"  @PreAuthorize ADMIN  body 可选 ReviewRequest → SwapVO
POST "/{id}/reject"   @PreAuthorize ADMIN  body 可选 ReviewRequest → SwapVO
// 可选 body：@RequestBody(required = false) ReviewRequest req，comment = req == null ? null : req.comment()
```

**实现要点**
1. 私有 `load(id)`：查不到 → 1600 `调班申请不存在`。
2. confirm、rejectPeer：status 不是 PENDING_PEER → 1608 `当前状态不允许此操作`；me.staffId 不等于 targetStaffId → 1609 `无权操作该申请`。
3. confirm：改为 PENDING_ADMIN，peerConfirmedAt=now，记 `CONFIRM_SWAP`。rejectPeer：改为 REJECTED，记 `REJECT_SWAP_PEER`。
4. cancel：status 不是 PENDING_PEER/PENDING_ADMIN → 1608；me.staffId 不等于 applicantStaffId → 1609；改为 CANCELLED，记 `CANCEL_SWAP`。
5. approve、reject：status 不是 PENDING_ADMIN → 1608。
6. reject：改为 REJECTED，写 reviewedBy=me.id()、reviewedAt、reviewComment，记 `REJECT_SWAP`。
7. approve 用私有 `shiftOf(staffId, date)` 取当前已发布班次，取不到 → 1602 `排班已变化，请驳回后重新申请`。按 type 计算 changes：
   - LEAVE：`[(A, dA, "L")]`；
   - COVER：`s = shiftOf(A, dA)`，得到 `[(B, dA, s), (A, dA, "X")]`；
   - SWAP：对 `{dA, dB}` 去重后的每一天 d：`a = shiftOf(A,d)`、`b = shiftOf(B,d)`，加入 `(A, d, b)` 和 `(B, d, a)`。
8. approve：`schedule.applyChanges(changes, "调班 " + no, me.id())`；改为 APPROVED，写 reviewedBy、reviewedAt、reviewComment，记 `APPROVE_SWAP`。
9. 所有方法日志 target 都是 `TB-xxxx`；返回 `toVO`。

**验收标准**（Mockito）

| 用例 | 期望 |
|---|---|
| PENDING_PEER，对方 confirm | PENDING_ADMIN，peerConfirmedAt 非空 |
| PENDING_PEER，第三人 confirm | 1609 |
| APPROVED 后 cancel | 1608 |
| approve LEAVE（A 10-12） | applyChanges 收到 `[(A,10-12,L)]`，状态 APPROVED |
| approve COVER（A 10-12 为 N） | 收到 `[(B,10-12,N),(A,10-12,X)]` |
| approve SWAP（A 10-12=N、10-13=D；B 10-12=D、10-13=N） | 收到 4 条：A 10-12→D、B 10-12→N、A 10-13→N、B 10-13→D |
| approve SWAP 同一天（dA=dB=10-12，A=N，B=D） | 收到 2 条：A→D、B→N |
| approve 时某格已无已发布 | 1602，不调用 applyChanges |
| id=999 | 1600 |

- curl：接 M3-04 的请假申请，科长 `POST /api/swaps/{id}/approve` → `status=APPROVED`；成员 `GET /api/schedules/{该月}` 中本人该日为 `L`。

**规模**：约 200 行。**依赖**：M3-04、M3-01。

**接口定义**

```java
/** counts：所有班次代码 → 天数，按班次 sort_order 排列，没有的为 0 */
public record StatsRowVO(Long staffId, String empNo, String name, Map<String, Integer> counts,
                         int offDayWork, BigDecimal totalHours) {}
public record StatsVO(LocalDate from, LocalDate to, List<StatsRowVO> rows) {}

@Service
public class StatsService {
    public StatsService(SchedulePublishedEntryRepository publishedRepo, StaffRepository staffRepo,
                        ShiftTypeRepository shiftRepo, ScheduleQueryService query);
    public StatsVO stats(LocalDate from, LocalDate to, AuthUser me);
}

@RestController @RequestMapping("/api/stats")
@PreAuthorize("hasAnyRole('ADMIN','MEMBER')")
GET "" ?from=2026-10-01&to=2026-10-31 → StatsVO
// 参数写法：@RequestParam @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate from
```

**实现要点**
1. from 晚于 to → 1700 `开始日期不能晚于结束日期`；`ChronoUnit.DAYS.between(from, to) + 1 > 366` → 1701 `统计范围不能超过 366 天`。
2. 人员：`findByActiveTrueOrderBySortOrderAscIdAsc()` 中 schedulable 的；非科长只保留 `staffId == me.staffId()` 的一行（staffId 为 null 时 rows 为空）。
3. 班次：`shiftRepo.findAllByOrderBySortOrderAsc()` 转成 `Map<code, ShiftType>`，保持顺序。
4. 数据：`publishedRepo.findByWorkDateBetween(from, to)`；日历：`query.calendar(from, to)`。
5. 每条数据：该人 counts[code]+1；班次 `isCountsAsWork()` 且 `cal.isOffDay(date)` 时 offDayWork+1；totalHours 加该班次的 workHours。

**验收标准**（Mockito）

| 用例 | 期望 |
|---|---|
| A：10-05 D、10-10 N（周六）、10-11 X；D=8h、N=14.5h | counts D=1、N=1、X=1、Z=0；offDayWork=1；totalHours=22.5 |
| 国庆 10-01~07 放假，A 10-02 Z(24h, countsAsWork) | offDayWork=1 |
| 成员调用，有 A、B 两人数据 | rows 只有本人 |
| from=10-31、to=10-01 | 1700 |
| from=2026-01-01、to=2027-01-02 | 1701 |

- curl：科长 `GET /api/stats?from=2026-10-01&to=2026-10-31` → `code:0`；大屏账号 → HTTP 403。

**规模**：约 160 行。**依赖**：M2 全部。
